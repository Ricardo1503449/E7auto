## 行为与文档职责

发布批次采用“完成修改及相关测试→同步版本和文档→构建验收→集中提交推送→Release”。README使用固定下载入口，随包说明在构建前定稿，发布检查单只保留通用步骤。版本验证结论在最终提交前整理；上传/远端核对结果留在GitHub和本地产物，避免发布后追加状态文档提交。已有v1.3.3等历史验证记录保留原事实。

`scripts.release.workflow` 提供preflight、capture、seal和check四个入口，已接入现有构建脚本及带 `--run-dir` 的发布验收：

- preflight核对项目、源码、README、随包说明及CHANGELOG版本，拒绝已列入规则的临时发布状态描述。
- capture在编译前保存构建输入的原始摘要和Git对象标识，允许输入尚未提交；新增或删除输入文件同样纳入检查。
- seal在最终ZIP替换前检查输入未变、ZIP与独立目录逐文件相符、资源/配置/说明与输入快照相符。
- 发布验收将编译版自检结果绑定到该构建；check在最终提交后检查Git输入集合、工作区输入、ZIP身份和已通过的编译验收。只补未打包的验证记录不会使构建失效。

文本按Git实际行尾/属性过滤规则核对，PNG/ICO要求Git中保留原始字节。工具不会自动commit、push或发布，也不会把已有包补登记成新流程构建。
