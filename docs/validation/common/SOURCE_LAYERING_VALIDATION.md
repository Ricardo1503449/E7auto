## 2026-09-16 后续UI生命周期修复

后续诊断中，同样的28项UI用例原样连续运行仍发生原生退出；临时禁用循环GC、在用例间主动回收、或把标题栏/缩放控件的主窗口回指改成弱引用，均能使该组通过。这些是受控诊断，不是提交关闭GC的修复。

专项修复将两个控件的反向强引用改为weakref，并在操作前同时检查引用存活与PySide包装对象的C++有效性。主窗口仍拥有子控件；生产窗口关闭语义不变。UI测试新增局部conftest，统一QApplication与本用例窗口清理，显式处理延迟销毁及计时器；通用测试helper不导入Qt辅助代码。

验证结果：

- 只修改生产代码、尚未加入清理fixture时，原28项UI测试在同一个进程通过，循环GC开启。
- 新增7项生命周期回归覆盖主窗口不被子控件保活、Python引用过期、C++对象已销毁、拖动/缩放派发、窗口与浮层/计时器实际销毁，以及两种关闭方式的原生压力回归。
- 使用本次修复前的真实window_chrome源码作为子进程对照，新增“主窗口必须释放”用例按预期失败，引用仍指向MainWindow；新实现通过。未以调整原断言掩盖问题。
- 最终 `tests/ui` 的38项用例在同一个pytest进程连续通过，退出码0。两个压力用例各在独立进程运行30轮创建、功能切换、浮层收起/恢复和关闭；仅close路径不显式调用gc.collect，显式销毁路径验证测试清理。两者均确认窗口包装对象及原生窗口无残留、循环GC开启、WGC/WinRT未加载。
