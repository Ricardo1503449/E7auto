# 自动卡厄思阶段拖动与切换

## 实现结果

用户要求优先启用阶段切换，原“非第1阶段停止”调整为自动切换到第1阶段后继续开局。

1. 同时确认大厅研究选项和开始探查按钮。已识别第1阶段则不打开选择面板。
2. 非第1阶段时，由开始探查按钮的实测位置计算其上方阶段栏右侧双箭头点击点；校验点击点在阶段栏范围内且位于开始按钮上方。
3. 打开面板后，只在已批准的右侧阶段列表中寻找01；不可见时向下拖动以显示更早阶段。
4. 每次松开后重新定位；选中01后同时确认该行高亮框、左侧难度1及选择按钮，再提交一次。
5. 回到大厅并确认第1阶段后才允许开始探查。拖动无进展、证据矛盾、提交未确认或页面异常时停止。

## 后台拖动与停止边界

平台端新增按下、按住移动、释放三种窗口消息操作，不调用物理鼠标移动接口。运行层按步派发并分别使用F5互斥锁，避免整个手势长期占锁。

- 每步确认窗口、F5和有效期限；拖动前、拖动中每100ms及松开后检查网络和页面。60ms短手势不在每一小步重复完整截图识别；检查到重连时先释放，再执行既有重试流程。恢复后重新确认选择面板，不继续使用旧列表位置。
- F5或异常打断后只清理已按下的按键，不追加移动、点击确认或退出。
- 释放仍核验窗口身份，不向已被其他进程复用的句柄发送消息。窗口缩小或最小化后允许向原窗口发送释放清理。
- 当前参数：相对开始按钮的入口偏移 `[250,-125]`；阶段列表内起点 `[0.55,0.30]`；配置 `drag_steps: 6`、`step_distance_px: 500`，按住一次分6步向下移动，累计3000基准像素；间隔至少10ms，名义时长60ms。释放后等待500ms并重新取得连续3帧稳定位置；最多12次完整拖动、45秒有效处理时间。重连不消耗业务时间预算。
- 基准消息从 `(1675,338)` 依次移动到Y为838、1338、1838、2338、2838、3338的位置后释放；各点按实际客户区缩放。超出可见客户区的坐标仍只发送给原游戏HWND，需显式开启且已有合法按下，保留有符号16位消息范围限制。普通点击、按下和默认移动仍拒绝越界；不改变物理鼠标位置。
- 10ms是两次移动之间的最小计划间隔，窗口检查、截图识别和系统调度可能加长实际耗时；不以压缩后续间隔追赶进度。游戏能否接受这组长距离快速消息，不能由消息派发测试代替实测。
