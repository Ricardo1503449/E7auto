# 原图匹配与尺寸适配

2026-10-01：商店、企鹅、卡厄思以及共享入口、网络和跨日控件使用统一坐标接口，基准与非基准识别自动分流。正式模板、识别阈值及业务提交顺序保持不变。

## 坐标与截图

`vision/frames.py` 的 `FrameView` 保存原始像素、基准到完整客户区的变换以及子视图的全局原点。配置搜索框向外取整一次；`region(roi, *, clip=False)`与`crop(roi, *, clip=False)`默认要求完整区域位于当前视图内，越界抛出ValueError。动态局部搜索、合法配置区域与子视图的交集、候选透明边距处理显式使用`clip=True`，完全不相交时返回空区域或空视图。固定区域、数字、滚动和卡片内容不静默截断；空区域或缺少完整有效模板支持不得作为命中证据。两种尺寸共用上述契约，不重采样截图，嵌套裁剪不重新计算比例。

配置继续使用2322×1306基准下的Point/Rect。匹配结果的ClientRect和ClientPoint表示实际客户区像素。Observation分别记录bounds、search_region、anchor、颜色分数、结构分数和candidate_id，废除含义不一致的Observation.roi。输入守卫对配置点转换一次，对ClientPoint直接发送；窗口、DPI、显示器变化和停止守卫保持原行为。动态区域、模板外偏移按客户区比例转换，模板内相对锚点按实际命中尺寸计算。

本方案不增加黑边、任意宽高比、响应式重排支持，也不改变WGC新帧超时处理。1:1截图可以直接传递；匹配器仍将其包装为同一原图视图。

## 基准路径与保护边界

完整客户区等于配置baseline_client_size（目前2322×1306）时，未声明分部布局的普通匹配入口仍转到vision/baseline.py，恢复首次原图迁移前已经验证的OpenCV评分、粗定位和局部验证策略。原始模板及遮罩不缩放；原有粗定位保留AREA图像、NEAREST遮罩及局部±5像素搜索。结果适配为现有Observation、MatchGeometry及ClientPoint/ClientRect，不恢复旧Observation.roi的混合语义。

事件两种尺寸共用原二/三选项分组并行调度、组内索引顺序、命中取消及身份复核；仅候选像素验证分流。1:1路径使用原参考位置/局部/半尺寸提案验证，每个发现帧在主线程生成一次只读半尺寸粗定位图供两组共用，缓存复核帧不生成，也不跨帧保存截图。战利品图标/全名恢复原OpenCV区域评分；自动战斗按2026-10-02用户授权，两种尺寸共用AutoIconState静止参考角度判定；基准原字形仍使用固定中心，不参与局部搜索或缩放。各专用入口依据父帧的完整变换分流，不能通过裁片大小重新推断尺寸。基准粗模板缓存使用独立键并计入现有LRU字节预算，不影响非基准候选的采样规则。

基准尺寸路径是正式保留的稳定实现，不视为待淘汰的兼容代码。后续以非基准尺寸适配为目的的优化，默认只修改非基准分支，不得自动替换、合并、删除或改变已验证的基准搜索、评分、定位和确认行为。公共接口或共享工具修改须核对基准影响；确需改变基准行为时，单独说明原因、影响范围和验证方案，并取得用户明确授权。非基准适配请求不构成基准改造授权。相关验证按实际影响范围执行，复用未变结果，不自动扩大到全套测试。

2026-10-15经用户明确确认，卡厄思事件入口首次发现的空标题快速返回共用于基准和非基准：按现有前景规则提取的二/三选项标题特征全部为空时，本帧直接返回未命中，让调用方继续取新帧，不启动发现线程池或逐个验证完整事件模板。任一标题槽位有特征仍进入原分组排序及完整模板验证，不要求每个选项标题都有特征；基准和非基准分别使用各自保留的匹配后端。已有候选优先在当前像素上复核。此处理不缓存空帧结论、不增加识别时间预算，也不改变原15秒页面超时、文本三角优先顺序、三帧确认、点击及停止/网络守卫。

同日经用户确认，全部卡厄思事件选项共用`events/choices.py`的阶段确认及有限重试。仅在原阶段的同一选项新帧连续三次稳定命中、尚无后续页面证据时，以最新Detection的ClientPoint补点，间隔至少1500毫秒、总计最多3次，保留首次点击起15秒有效期限。两条路径仍分别通过现有`ChaosVision.control`验证当前原图和生成客户区锚点；重试层不缩放截图或模板、不另算坐标、不更换搜索/评分/阈值。各处理器声明自身后续页面，网络恢复重建稳定证据但不重新计数或重放已完成阶段。

2026-10-16经用户确认，七类地图节点的有限补点及进入确认统一在ChaosFlow._enter_node完成，两种尺寸共用控制逻辑，未改节点/三角/进入模板、ROI、评分、配对、原匹配后端或原地图稳定及一次性交接。原节点及后续测量框在同一客户区空间判断唯一同类对应，最新ClientPoint直接交给原受控输入，不再次缩放。首次点击起15秒有效期限、1500毫秒间隔、最多3次（含首次）以及原守卫共用；可靠看到进入按钮后锁住节点补点，重连清稳定计数但保留次数、期限及该响应记录。事件4秒和其他节点300毫秒的提交后等待保持，不把业务重试变成通用识别预算或改变基准的搜索/确认算法。

## 非基准尺寸候选和证据

非基准模板按实际客户区比例采样，整数画布宽高只用于容纳结果，不再用取整后的宽高反推比例。非基准尺寸的候选使用每轴0、0.25、0.5、0.75的有限像素格相位，共16种；1:1由前述独立基准路径处理。候选画布带透明边距，记录真实内容尺寸、边距和相位。Observation.geometry保留浮点内容位置与真实比例，目标框最后向外取整，点击锚点从内容位置计算，不取透明画布中心。

缩小时按固定像素格做面积积分，放大时做线性采样；从原始模板一次投影预乘颜色和有效支持，再解除预乘。原uint8遮罩仍以非零为有效，输出float覆盖遮罩参与原颜色/结构门槛；不改正式PNG、不统一替换为最近邻遮罩，也不收紧文字遮罩删除暗笔画。组合模板先投影父模板，各部件从同一个采样网格提取。

全局颜色/粗定位只产生位置提案，随后在原图小区域检查有限相位，颜色和结构必须在同一候选、同一位置通过原门槛。半尺寸提案未能得到有效命中时，有界补做一次原尺寸提案，避免小字在粗定位中消失；这仍使用相同的候选和最终判定。离线exhaustive参数用于同算法完整搜索对照，不是旧识别方案。

已经确认的目标，仅在其去重范围完整覆盖某个局部提案的所有可能位置时，才跳过重复相位检查；未知位置继续检查。金框在两种尺寸下均先完成搜索和去重，再由阶段选择流程检查包含目标行且恰好一个结果；匹配器不接受业务包含条件来提前过滤提案或命中。不同身份沿用原歧义规则；候选相位不作为业务稳定性键。

小搜索窗口批量计算与OpenCV等价的masked SQDIFF/CCOEFF，模板统计数据只读并计入缓存。事件身份缓存另外保留已验证位置和相位的数值信息；后续帧先重新计算当前像素分数，失败才继续原有局部搜索。缓存不保存截图，不复用上一帧分数。

非基准搜索将当前ROI的方差检查、连续像素及补边准备与模板评分分开；半尺寸提案失败后的原尺寸补查沿用本次已准备的区域，不重新检查方差或补边。卡厄思一次事件发现的两组任务共用SearchPreparation，仅共享同一帧完整选项区域及按需生成的只读半尺寸图，不共享模板分数。不同局部ROI分别准备，不累积区域副本；准备对象及像素随本次调用结束释放，不进入TemplateMatcher或候选LRU，不跨帧复用。基准分流、原评分门槛、候选相位、定位和点击算法不变。实现与验证见[单次准备验证](../validation/common/PHASE_MATCHING_VALIDATION.md#2026-10-05非基准搜索的单次准备)。

`vision/components.py`在现有ROI中先验证主部件，再在同帧上验证关联部件。文字类以完整文字为主、图标为辅；阶数以阶级图标为主，数字为辅，1至5阶均保留图标与完整数字，5阶按2026-10-13用户授权去掉右侧`(Max)`。购买对象的两行文字一起验证。两个部件继承所属场景的颜色/结构门槛；企鹅原来只有颜色门槛，不额外添加结构门槛。两个分数取各自较低值，不用平均值掩盖弱证据。局部评分中分离的多个有效位置视为配对歧义，缺部件或不完整的有效像素不授权命中。

模板PNG和清单不变。YAML `component_matching`声明原完整模板坐标中的primary/secondary矩形与基准单位容差`[6,8]`；企鹅通过`penguin_component_matching`声明自身布局，共享日期恢复仅加载自身配置。加载器拒绝未批准身份、缺项、重叠和越界；识别初始化进一步检查两部分非空且覆盖原遮罩全部证据。未启用的阵容资源不读取图片。2026-10-17经用户明确授权，现有25张已选模板在基准和非基准尺寸共用分部匹配；没有扩大模板清单。基准使用1:1原始父模板像素和遮罩，沿用既有布局、颜色/结构门槛、横±6纵±8基准单位容差、配对拒绝及父模板动作锚点。无分部布局的模板仍按完整客户区尺寸走原匹配分流。三帧确认、业务流程、网络/停止守卫、事件、战利品及自动战斗识别保持原逻辑。

基准直接使用原始父模板，非基准先按同一真实比例和相位投影；部件仅取父模板的像素视图，并保留插值支持边缘及父对象引用。缓存条目和小窗口评分统计沿用现有LRU；视图不重复计算父数组字节，父数组在最后一个视图释放后才解除计费。局部搜索框向外取整，最终位移仍按实际`6*scale_x`、`8*scale_y`上限判断。以主部件还原完整父模板几何，沿用既有动作锚点与偏移。只在当前截图计算得分，不缓存截图，不在匹配器中截图、等待、点击或添加确认轮次。带结构门槛的常量有效搜索区域提前拒绝，其结果等价于原结构评分无法通过。

## 等待与输入守卫

250 ms硬预算、25 ms分块目标、500 ms通用证据复核及三个相关配置已撤回，Point不携带新轮次证据，FrameView不携带识别预算。恢复预算引入前的停止、窗口检查、网络恢复、业务总超时和连续确认；不再因识别超过250 ms而丢弃结果并重新截图。此前新增的通用位置提示缓存、分块评分、提前排除和跨帧重排也一并撤回，不加入替代识别预算。

## 缓存与生命周期

`vision/candidates.py` 提供按需生成的同步LRU，`vision.candidate_cache_mib`默认为64。预算包括新增RGB、float遮罩、缓存预处理及生成过程保守预留；原始模板、当前截图、OpenCV响应矩阵和既有索引需分别计量，64 MiB不是整个进程上限。

缓存键包含原始RGB与有效遮罩摘要、真实横纵比例、相位、预处理和算法版本。企鹅排除金额的派生遮罩拥有不同身份。一次仅允许一个生成任务，相同键等待并复用结果；数组发布后只读。淘汰不破坏使用中的引用，其字节仍计入预算，最后一个引用释放后扣除。预算不足在生成前明确报错，不静默扩容或跳过候选。客户区几何改变时清空旧候选，运行收尾释放缓存及自动战斗尺寸预处理。

不在缓存中保存截图。事件、战利品仍在每张新帧上复核已有身份；锚点指纹仅在完整原图搜索区、场景及模板身份都一致时复用完整搜索结果。

## 专用识别路径

| 路径 | 适配方式 |
| --- | --- |
| 普通控件、入口、网络和跨日 | 公共入口按完整客户区分流；基准使用已验证实现，非基准使用相位方案 |
| 商店商品与购买 | 原图匹配；槽位配置及购买点仍为基准单位 |
| 商店余额、企鹅价格 | 从原图分割，宽度/间距按轴缩放，面积按两轴乘积缩放；保留32×48字形分类器 |
| 地图、英雄、关卡、升阶 | 动态框和命中框均使用客户区坐标，基准几何参数显式转换 |
| 事件 | 二/三选项各一个可复用工作线程，组内按标题索引排序，首个完整命中取消其他搜索；候选匹配按尺寸分流，最终证据为原图模板匹配 |
| 战利品 | 基准使用原部件及OpenCV评分；非基准缩放完整父模板后提取图标和全名，共享一个采样网格；说明区仍不参与身份识别；三卡并行和歧义检查保留 |

| 商店滚动 | 基准/非基准共同使用商品内容候选、原图多分区验证及内容稳定确认；排除价格按钮并移除旧兜底 |

## 旧方案退役及验证边界

运行代码已移除AdaptedFrame、normalized_roi、ROI归一化缓存、旧归一化计数和frame_origin补偿，不提供旧非基准缩放算法的开关或失败兜底；已验证的1:1基准实现独立保留。数字字形归一化、索引缩图、粗定位缩图和展示缩图仍各有明确用途。

验证以真实宝箱和自动战斗失败截图、已有入口/升级/奖励等真实样本及其人工缩放版本为依据；组合模板补充合成布局。真实截图与合成场景必须分别记录，不能据合成通过声称实机全流程通过。新增候选不改变正式PNG。WGC黑屏无新帧问题单独处理，不能归入模板适配已修复范围。

采样相位修复及其验证范围见[修复验证](../validation/common/PHASE_MATCHING_VALIDATION.md)；初次迁移的历史结果见[原迁移记录](../validation/common/NATIVE_MATCHING_VALIDATION.md)。
