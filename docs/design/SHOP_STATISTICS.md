# 刷商店匿名统计

只对刷商店启用，使用已有的天空石扣除确认和商品购买成功计数，不修改识别、缩放、点击、重连或停止流程。初始商品的购买也计入该轮统计。数据池代表成功上报的客户端记录，不等于所有用户或游戏官方概率。

## 上报口径

正文严格只有五项：`run_id`为独立随机128位UUID十六进制字符串，`strategy`为`transfer`或`continuous`，`skystone_spent`为已确认消耗，`covenant_purchases`及`mystic_purchases`为成功购买次数。不上传版本、结束时间、账号、设备信息、日志或截图。运行日志原有编号保持不变。

两个池各显示三项总量和两项比率。比率按池内总购买次数除以总天空石消耗再乘100计算，不平均单轮比率；显示两位小数，分母为零显示“—”。包含初始商品，所以指标反映整轮获得效率。

## 本地与开关

数据文件为安装目录下`state/shop_reports.sqlite3`。每次已确认计数变化后写入累计值，不从文本日志重新提取，不保存识别帧。运行中的记录为active；结束后为pending，服务端永久拒绝的记录为rejected。重试次数、下次重试时间和取消代次仅供本地调度，不进入上报正文。

启动时将遗留active记录转为pending，恢复最后成功持久化的确认计数；断电发生在游戏操作与写入之间时，不推算最后一次未知操作。正常结束、手动停止、可处理的异常停止均收尾。正常终止时计数变化与最终信号重复出现也只生成一条记录。

默认开启。关闭时保留已有pending/rejected记录，取消当前未结束的active记录并暂停上传；本地偏好保存取消代次，避免数据库暂时不可写时，取消的记录在之后被误恢复。重新开启后补传旧记录，新一轮重新参与。

最多10000条，包括active、pending和rejected，不自动过期。满后静默跳过新轮次，不覆盖旧记录、不显示容量提示；已保存轮次仍可更新和收尾。设置页没有清空入口。覆盖升级保留state，卸载按现有安装规则删除state。

## 设置页反馈

统计条目与版本行之间保留分隔线。仅保留待上传记录数量及上传状态，二者统一使用14px和灰色#68717b；状态位于待上传记录和重试按钮之间，空状态不占高度。数量与按钮组距离标题增加12逻辑像素，重试按钮边框使用绿色#26985a。

点击“重新上传”后立即显示“正在重新上传…”，按钮显示“上传中…”及旋转进度，并在请求排队或进行中禁用，防止重复提交。完成后刷新数量并恢复“重新上传”按钮文字；没有可重试记录时继续禁用。关闭统计、任务运行中、未配置服务地址、没有可重试记录或本地存储错误时，显示明确原因，不停留在上传中。运行或准备任务暂停正在进行的上传时，先显示暂停原因，再结束忙碌状态；关闭页面停止不可见的旋转动画，返回后按实际请求状态恢复。

手动和后台上传成功统一显示“统计记录已上传”。设置页未显示时保留成功提示，不开始隐藏计时；用户打开设置页，或成功发生时已在设置页，显示3秒后清除。成功提示显示期间离开设置页，立即清除并取消计时，返回后不重复显示；离开之后新收到的后台成功提示仍保留至下次打开。失败及其他说明不定时隐藏，新的结果替换旧结果，并取消旧成功提示的计时。

## 上传与隐私

独立Qt工作线程读取Windows系统代理值，未配置代理时直连；不修改全局代理。应用准备或运行自动化时暂停统计请求，停止后恢复。单次请求超时10秒。暂时失败按1/5/30/60分钟退避，之后每小时重试，遵守更长的Retry-After；连接级退避避免在服务中断时逐条轰炸积压记录。退出时中止请求并保留数据。

仅接受HTTP 200/201、accepted=true且编号一致的确认才删除本地pending记录。响应丢失、重定向、无效确认、网络或服务错误均保留；400/409/413/422只隔离该条，其他记录继续。手动重试重置暂时失败的等待，不重新激活永久拒绝记录。

请求结束时先检查HTTP状态、网络错误及响应可读性，只读取需要核对的成功回执；超时或响应过大被中止后不读取已关闭的响应，避免device not open警告。失败日志记录HTTP状态和Qt网络错误类别/说明，不记录或上传请求正文；超时、响应过大和无效回执分别给出固定可见提示，待上传记录与既有退避规则保留。

Worker用唯一运行编号和插入触发器原子更新两个池。相同编号相同内容只确认一次，不重复累加；内容不同返回409。基本防护包括字段/整数/数量边界、2 KiB正文限制及每来源120请求/分钟的宽松限流。来源限流键不写入业务数据库；共享代理或NAT可能被暂时限流，客户端继续补传。匿名上报无法证明数据来自真实游戏，不引入登录、硬件标识或客户端共享密钥。

## 展示与迁移

Workers公开汇总JSON、SVG和详情页，不公开逐次明细。汇总更新时间由服务端生成，区别于未收集的用户结束时间。详情页前台每60秒刷新，失败保留旧结果；README图片受GitHub缓存影响，不承诺秒级变化。

详情页及README使用的SVG按“转运池”“连续刷新池”分为两个独立面板，每池完整展示五项指标。天空石总消耗用大数字；两种商品的累计购买和每100天空石购买次数分别配直接标注数值的条形图。两池同类图共用从零开始的比例，购买次数与比率不混用尺度。零总量的条长为零，未定义比率仍显示“—”，不补模拟值。详情页不含JSON链接、折叠的重复指标或页尾解释段落。

页面固定亮色背景、白色面板及纯黑指标文字；转运池统计条和圆点为#5BC7A4，连续刷新池为#73B6E6。大标题为“两种策略效果展示”，上方保留原版“E7AUTO · 社区统计”小标题：#228A50、13px、字重700、字距0.12em及原字体/行距。天空石标签16px，累计购买和获得效率标题15px，其余指标标签14px。宽屏并列、窄屏上下排列，不添加悬浮提示或图表运行依赖。

配色及初始条宽在外部样式文件定义，遵守既有只允许同源脚本/样式的内容安全策略。HTML使用no-cache，样式与脚本链接使用由各自内容生成的版本标记，避免展示更新后混用旧资源。读取数据后的条宽只由已验证汇总更新。

GitHub Actions工作流启用后，计划每日北京时间02:17向独立stats分支保存累计汇总JSON、同源SVG及日期历史，使用单次JSON生成图，避免两次请求之间的新上报造成不一致。快照日期取实际执行时的北京时间，同一天重跑更新该日期文件，旧提交仍保留；不把累计值解释成当天新增量，不补算漏跑日期。获取或校验失败不发布零值；分支更新不强制覆盖并核对实际引用，保留既有历史，不修改源码分支。默认分支、变量、权限和首次执行验收见[部署说明](../development/SHOP_STATISTICS.md#github每日快照)，源码中存在工作流不代表远端已经启用。

首期严格免费。服务额度不足时允许暂时接收失败；不自动升级付费。D1逐次数据不自动删除，容量用尽时需由维护者决定迁移方案。后续更换后台时沿用五项接口、UUID和去重规则，并迁移已接收编号及累计结果，避免重复计数。
