# 后台统计与活跃安装

## 客户端策略

自1.5.2起统计统一后台启用，设置页不提供统计开关、数量、状态或重试按钮。本次功能的进度、购买计数和停止结果仍为正常运行反馈。用户说明移除旧统计操作介绍，不新增自动统计介绍。

旧偏好中的shop_statistics被移除，shop_statistics_generation保持单调；旧关闭安装迁移时递增一次代次，隔离包括无旧代次字段在内的遗留active记录，已存在pending/rejected记录沿用原状态，未采集的数据不补造。偏好迁移写入失败不会阻断启动，后续启动重试；内存仍使用递增后的代次并启用。其他通知、公告、刷新模式和阵容偏好保留。

## 两类上报

商店仍使用POST /v1/shop-runs，五项字段run_id、strategy、skystone_spent、covenant_purchases、mystic_purchases保持兼容；运行编号随机、每轮独立。两个池按累计购买次数除以累计天空石再乘100计算，包括初始商品；记录去重与累计值永久保留。

活跃使用POST /v1/usage-days，正文仅installation_id、date、version、features。安装标识为随机128位UUID，不使用账号或硬件标识。日期按北京时间；功能值为shop、penguin、chaos。仅正式编译版主窗口显示后采集，源码、自检不产生正式活跃记录。实际收到非准备、非终止的功能运行快照后才记功能使用，准备失败或取消不记；持续打开和运行跨日时归入新日期。

每日合并功能集合和较高版本，同安装同日重复启动不新增活跃安装。每次内容变化增加本地revision，回执只确认已发送的revision，不能丢弃请求期间新增的功能。商店和活跃使用同一上传线程交替调度，分别保存与去重。

网络线程逐请求读取系统代理，不更改全局代理；准备、运行及更新忙碌时暂停上传，空闲恢复。临时失败沿用1/5/30/60分钟退避和更长Retry-After，退出中止请求并保留有效记录。失败不弹统计提示，不阻断主功能。永久拒绝的记录不会无限请求。不上报账号、硬件标识、日志或截图。

## 本地记录与回执

两类数据库均位于安装目录的state下：state/shop_reports.sqlite3保存商店运行记录，state/usage_reports.sqlite3保存随机安装标识及每日活跃记录。覆盖升级保留state，卸载按原规则删除。

商店记录取得服务端有效成功回执后，删除对应的pending记录；数据库文件保留。活跃记录取得成功回执后只推进acknowledged版本，不立即删除当天记录，便于后续同日功能和版本变化继续合并；新revision仍需上传。

客户端每次记录新活动时，按北京时间保留当天及此前89天的日记录，清理更早记录；随机安装标识不随日记录清理。软件关闭期间不执行此清理，下次记录活动时再处理。

未获有效成功回执的记录保留，临时失败按退避规则补传，永久拒绝的记录保留并隔离；日活记录仍受上述90日清理规则约束。成功回执不删除两个SQLite文件，也不清除随机安装标识。

## 服务和保留

上报服务只提供上述两个POST入口，字段白名单、2KiB正文及来源限流继续生效；其他路径404，上报路径其他方法405且Allow为POST。旧页面、SVG、脚本、样式及汇总读取实现已退役，不跳转到新的统计页面。上报地址继续来自config/internal.yaml，具体网页地址和部署配置在私有统计仓库维护。

usage_days按安装和日期唯一，原子合并功能位与版本，延迟包不覆盖同日较新版本。未来或非法日期拒绝；超过保留期的活动确认接收但不插入，允许客户端确认过期积压。服务端活跃明细保留最近90个北京时间日期，每日清理；商店runs/pools不参与清理。

统计网页读取同一D1，仅输出汇总，展示今日、7日、30日的打开安装数、实际功能运行安装数、分功能安装数及活跃版本。每个时间窗按安装去重，不能将每日人数相加；版本按期间最后活跃日、同日较高版本归类。主要指标为30日实际运行安装数。离线、旧版本和忙碌暂停可造成延迟，不等于人数或实时在线人数。

## 私有维护与历史

私有仓库E7auto-stats保存网页、配置、快照工具及原公开stats分支的完整历史。网页按维护者选择保持免登录；知道网址者仍可读取汇总。公开项目不记录新网页的具体网址。

原公开快照工作流先停用。迁移核对提交SHA及文件树哈希后删除公开stats引用；主仓库README撤下统计展示。已有Git历史、验证记录和历史Release保留，不承诺收回克隆和缓存。

私有工作流每日抓取一次汇总，JSON与SVG来自同一份数据，按北京时间归档；仅保留当前365日JSON及最新SVG，不补算漏跑日期，完整Git提交历史保留。发布前强制检查目标仓库为私有，基于原tree更新数据文件，不覆盖网页源码、工作流或README，不强推。定时触发可能延迟。
