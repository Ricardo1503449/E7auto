# 自动卡厄思实施计划（模板复用同步版）

本计划以用户确认的原实施计划为基础，同步模板审核、按钮复用和正式登记结果。功能显示名称为“自动卡厄思”，内部标识为 `chaos`。业务顺序、节点优先级、轮次计数和异常停止规则沿用原计划。

## 2026-10-16 地图节点有限点击重试

按用户确认，普通、精英、首领、修整、补给、事件、商店共用`ChaosFlow._enter_node`，基准和非基准使用相同重试规则。首次仍按原优先级选择并点击一次；后续仅在原楼层的当前可选节点中复核原目标，不重新运行优先级。目标须为同类型、当前图标中心落在首次测得节点框内且恰好一个候选，位置连续三张新帧稳定，距上次节点点击至少1500毫秒才补点；使用最后一帧锚点，总计最多3次（含首次）。无法确认地图、楼层不符、目标消失/移出原范围、歧义或位置不稳时不补点。

新帧首先检查`node_enter`，任一可靠命中即记录节点已有响应，永久停止本阶段节点补点；该记录跨重连保留。按钮仍连续三帧确认后只点击一次。自首次节点点击前开始保留15秒有效期限，重试和重连不重新计时或补回次数，网络恢复仅清空稳定证据；次数用完且原目标仍稳定可选时停止。原地图一次性交接、手动停止、窗口检查、事件进入后4秒等待及其他节点300毫秒等待保持。参数独立放在timing.map_node_retry_ms/map_node_max_attempts，原匹配实现与模板不变。验证及现有招募测试失败边界见[运行验证](../validation/chaos/RUNTIME_VALIDATION.md#2026-10-16-地图节点有限点击重试)。

## 2026-10-16 事件选项展开检查

按用户确认，在公共入口首次完整搜索之前检查标题组合是否完整、位置及局部对比度是否稳定；基准与非基准共用。复用已有二／三选项布局和标题区域，从原图提取局部灰度对比特征；每套组合内所有标题必须按同一偏移对齐，采用最弱标题得分，禁用标题即使索引排序权重为0也参与完整性检查。连续新帧满足原稳定帧数（3）后才运行原二／三组并行索引与完整匹配；预检查不确认事件身份、不提供点击坐标、不删减候选。

标题缺项、移动、淡入或不稳定时直接返回等待新帧；保持文本三角优先、原15秒页面期限、网络与停止守卫。文本、输入、重连、几何变化、候选复核失败及入口结束清空就绪证据，仅保存数值特征和计数，不保存截图。完整模板评分、原三帧身份确认、事件路线及选项重试不变。运行参数在`event_recognition.readiness`；实际图片、流程及限制见[运行验证](../validation/chaos/RUNTIME_VALIDATION.md#2026-10-16-事件选项展开检查)。

## 2026-10-15 全部事件选项接入有限重试

按用户确认，53个全局事件入口身份及祭服的两个第二阶段状态、武器库第二组选项统一接入`EventContext.choose`；二/三选项的既有索引、原匹配后端和选定路线保留，基准与非基准共用重试规则。具体处理器声明后续页面：文本/原楼层地图、直接奖励卡、事件战斗准备、升阶入口、招募页、离队页，或本事件内部的下一组选项；四条经验路线仍显式调用原经验收尾模块，不向普通文本收尾添加升级分支。

首次点击后持续在新帧检查后续结果；任何后续证据先阻止补点，确认后结束本阶段。只有同一原选项连续三帧位置稳定、间隔至少1500毫秒，才按最后一帧的锚点补点，总计最多3次，原15秒阶段期限不随重试重置。未知/消失/不稳定画面和不完整升级弹窗不授权补点。停止与窗口检查沿用受控输入；重连清空稳定证据，保留阶段、已用次数和有效期限。记录`chaos_event_choice_retry`，超限详情包含选项、次数及当前等待阶段；保留各原路线的超时原因分类。

祭服首次“拿走祭服”以第二组选项为结果，第二次“染上红光”以文本或地图为结果，二者独立计数。武器库的两次选项分别以对应事件战斗准备为结果，确认进入战斗阶段后不再重试已完成的选择。奖励关闭、战斗开始、升阶及离队提交继续使用各自既有能力，不接入选项补点。实际验证及限制见[运行验证](../validation/chaos/RUNTIME_VALIDATION.md#2026-10-15-全部事件选项有限重试)。

## 2026-09-24 已实施：事件入口、索引与文本收尾优化

本节记录本轮已落地的入口、索引和收尾流程。44个入口事件已全部制作标题索引元数据（二选项22个、三选项22个），实现位于`features/chaos/event_recognition.py`。图片验证、行为测试和离线计时范围见[运行验证](../validation/chaos/RUNTIME_VALIDATION.md)，源码验证不等于实机提速验收。

- 仅事件节点的进入按钮点击后，将原约300ms等待替换为总计4秒的可中断等待。之后每张新截图先检查一次文本三角形；可靠命中则点击，按原约300ms动作等待后重新截图，继续优先检查三角形。三角形未命中才尝试事件选项识别；选项也未确认时回到新截图的三角形检查，不永久锁定为选项阶段。保留现有超时、网络有效时间、手动停止及窗口守卫，不增加重连后重置完整超时的策略。
- 事件索引以现有模板中的整组选项标题图像为主，保留标题笔画与布局，专属标题优先、通用离开等低区分度内容降低权重。分别建立二选项、三选项索引，运行时按两种布局提取标题特征，分数按有效文字量/标题权重归一化；不以预先数出的选项数量作为硬排除条件，也不将不同布局拉伸成相同图像。索引仅给候选排序，不能单独授权点击。模板像素保持原样；运行所需布局及标题区域等元数据写入功能配置，不从历史校准记录动态读取。
- 自动化流程线程负责截图、归一化和公共预处理；两个可复用识别线程分别完成二选项/三选项的候选排序与完整模板验证。静态模板/遮罩预处理按模板缓存，每帧公共预处理按帧复用，线程只读取图像和索引。按用户取舍，首个通过原颜色/结构门槛的事件作为候选，停止安排剩余候选验证，已运行任务安全收尾；取消首次强制全库唯一性检查。候选靠前项未通过时可以扩大候选范围，不强制每帧扫描全库。
- 首次命中后的两张新截图只复核该候选，优先在原命中位置附近查找，完整识别阈值与三帧稳定要求保留。复核失败、网络恢复、文本三角形出现、输入或离开当前入口等边界清空候选和稳定计数；点击取最后一帧的有效锚点。线程不截图、不点击、不逐帧写日志。
- 事件自有流程完成后，公共收尾同样改为三角形优先：单次可靠命中就点击并按原动作等待重新截图；三角形未命中才检查原楼层地图。地图连续三帧稳定确认后结束事件，否则回到三角形优先检查。收尾不增加4秒等待，不重新识别/分派事件身份。
- **覆盖现有及后续新增事件。**公共入口、索引检索、候选复核、线程池/预处理复用和文本收尾由公共能力统一提供。新增或替换事件选项模板时，同步事件资源键、二/三选项布局、标题区域/索引元数据及独立处理器绑定；配置校验必须发现已登记入口事件缺少索引元数据或绑定，不能静默漏入索引或另走旧的全库串行路径。具体事件仍只负责其选项选择、战斗/奖励/升阶等自身步骤，并复用现有卡片关闭能力。模板审核及登记流程继续适用。

## 2. 首版范围

- 从游戏主界面启动，按正整数预设轮数完成三层探查，最终回到主界面。
- 从下拉框选择第1—5阶段；每轮大厅已为目标阶段时直接继续，否则打开阶段选择，必要时向下拖动列表至顶部寻找目标数字，确认目标行高亮后提交。回到大厅确认目标阶段才开始探查；稳定顶部未找到可选目标或确认失败时停止。大厅五种身份全部加载比较，多个候选时最高分至少领先次高分0.02才确认；任一必需身份缺失或损坏时拒绝启动。
- 英雄筛选后只搜索右侧可见列表，不滚动寻找。
- 只处理已登记事件和三选一战利品；未知事件或无法完成三选一识别时停止。事件战斗自动获得的奖励无需选择，已确认事件战斗上下文及关闭提示后可关闭；不识别、不记录奖励卡身份。
- 支持已登记的蘑菇及避难所战斗奖励升阶；不实现盗贼招募券特殊分支、重复特殊招募、中途恢复或无限轮数。
- 英雄死亡本身不停止；FAILED、超时、识别失败和其他异常停止。
- 手动停止终止整个自动化，不续跑、不补发退出点击；重新启动必须从主界面开始。
- 保留无关文件和修改。提交、推送、打包及发布继续按项目授权和发布流程执行。

### 3.2 场景配置与加载

每个识别场景独立配置：`resource.feature`、`resource.key`、搜索区域、颜色/结构阈值、点击锚点、动态定位规则及业务确认条件。

- 按 `(feature, key)` 去重检查和加载实际资源；多个场景引用同一份已加载图像。
- 复用场景使用已经交叉验证的资源及阈值。各自的搜索区域、按钮所在页面、操作前提、点击后的等待与确认仍分别维护。
- 例如首领与精英使用同一张蓝色奖励入口图片，但搜索位置、完成领取确认和后续招募券处理分别属于各自流程。
- 商店“离开”后等待离店提示或原楼层地图；提示及确认按钮连续三帧后确认一次，直接出现原楼层地图并稳定三帧则完成离店。修整和补给“离开”后确认地图。共用按钮图片不改变这些步骤。
- 未知场景、未知资源键或无效映射必须报错；不按名称相似度回退到其他按钮。
- 只加载本功能及明确依赖的公共网络资源。启用阶段选择和新增事件场景后，共206场景、199份专用资源及2份公共网络资源；7个灰态参考场景不成为运行依赖。
- 运行必需资源缺失或损坏时拒绝启动；其他功能专用资源缺失不影响本功能。
- 搜索区域、阈值和策略放在运行YAML中，动态目标位置由代码计算。模板来源裁剪坐标不能代替运行搜索范围。

批准映射已落实到正式运行配置 `config/chaos.yaml`；管理任务的 `results/resource_bindings.json` 和 `results/recognition_draft.yaml` 保留审核历史。运行程序不读取 `artifacts/`、审核HTML、登记历史、`scripts` 或 `tests`。

### 3.4 模板后续变更

原始RGB保持，不静默拉伸或重绘模板。修改模板、遮罩或搜索区域时，重新提供对应预览。正式PNG、清单和来源记录继续由登记工具逐项更新；候选经 `write_candidate_png` 导出，验证后单项prepare、核对、apply，写入串行。

当前三组按钮复用使用已批准图片，像素和遮罩未改，映射已获用户授权且完成登记，不需要重复制作或重复登记。

## 4. 基础接入与公共运行能力

### 4.1 架构

流程、识别契约、状态和策略放在 `src/e7auto/features/chaos/`，与商店、企鹅功能平级，组合共享运行服务，不导入或继承其他功能流程。

bootstrap显式组装配置、识别、流程、启动请求和停止策略。同步功能中心入口、设置页、工作线程分发和发布资源校验。运行识别接收内存图像；保留既有后台输入约束、平台接口和WGC延迟导入规则。

加载层实现第3节的场景到资源映射及去重，不为旧场景名恢复重复PNG。资源清单和运行配置随包分发；来源、审核和登记历史不成为启动依赖。

### 4.2 设置与悬浮窗

设置页复用现有样式，提供“完成轮数”正整数输入及启动按钮，默认1轮。

```text
已耗时：0时0分0秒

已完成轮数：0 / 预设轮数
战败次数：0
当前状态：运行中
```

状态限定为运行中、重连中、已完成、已停止。复用现有拖动、收起、展开和停止后关闭行为。运行快照新增本功能目标轮数、完成轮数及正常完成状态，不使用企鹅购买计数。异常或手动停止后保留最终显示并清理内部局内状态；达到目标且返回主界面后才发布“已完成”。

战败次数由运行快照独立累计：三帧确认FAILED并交回轮次流程时立即加1，回收失败也保留已确认战败；自动重开和网络恢复不清零、不重复计数。新任务从0开始，识别超时及手动停止本身不算战败。仅卡厄思悬浮窗显示该行，停止日志同时记录defeats。

### 4.3 状态、网络与时间

局内记录当前层数、选中节点类型、进入本场战斗前绑定的层数、英雄等阶、自动战斗是否确认、待上阵英雄及奖励处理进度。

- 按所选阵容将初始四人记1阶；暗双子队途中招募律荷成功后新增1阶记录，平民替换队初始已有律荷，不重复招募。状态跨节点、跨层保留，新一轮按阵容重置。
- 升阶、招募、领取和轮数各只记录一次。
- 普通、精英及前两层首领战每1秒先检查升级标题、未命中同帧补查VICTORY，任一首次命中后进入可提前结束的3秒升级观察窗口；单场最长10分钟。升级关闭后沿用本场剩余期限快速确认后续结算，下一场重新开始升级优先检查；第三层首领和事件战保留5秒结果轮询。首次进入探查和普通页面切换/操作结果等待15秒，独立配置。
- 普通控件及地图确认沿用100毫秒采样、连续3帧。上下跳动的文字三角在事件入口/收尾使用单帧可靠命中，不要求坐标三帧一致；沿用点击后300毫秒等待并优先识别新选项或原楼层地图。动画与旋转参数仍保留待实机校准范围。
- 全流程持续识别网络异常；战斗等待时至少每1秒检查网络，升级/VICTORY检测复用同一守卫画面，不另起奖励入口轮询；仅本场重连后增加关闭提示/结算接续检测。
- 所有业务超时、采样间隔和轮询期限使用扣除重连时长的运行时钟；悬浮窗显示实际经过时间。
- 重连后丢弃旧帧和未完成稳定证据，重新确认当前页面与操作结果。购买、招募、升阶和领取不能盲目重复提交。
- 手动停止在等待、重连及操作边界均能终止；停止后不得新增游戏输入。

## 5. 业务实现顺序

### 5.1 入口、开局与初始招募

从主界面进入战斗分类、次元探查介绍页和大厅，以研究选项及开始探查按钮确认大厅。已识别目标阶段则直接继续；其他阶段通过开始探查按钮的相对位置定位阶段栏切换图标，打开选择面板。

右侧列表识别不到目标条目时，在已批准的 `stage_list` 区域内按下并向下长拖动，松开后重新识别。起点、步数、单步基准位移、步进间隔、画面检查间隔、稳定等待、次数和时间上限均在 `config/chaos.yaml` 的 `stage_selection` 配置中维护。分6步、每步500基准像素，总位移3000像素，移动间隔至少10ms；总名义移动时长60ms，不含悬停、窗口核验和识别开销。消息坐标允许超出可见客户区，不裁短总位移；仅向已按下的原游戏窗口派发，不移动物理鼠标。松开后等待500ms，再要求01连续3帧位置稳定后选择。未找到则最多重试一次，默认总共最多2次完整拖动，有效阶段处理时间15秒，网络重连耗时不计入。不能仅按累计位移断言已到顶。

选择目标条目后，必须同时识别目标数字、包围它的高亮边框及选择按钮，才提交一次。恢复到大厅并再次识别目标阶段后才能开始探查，再选择雇佣契约并确认选中。每步检查手动停止、窗口和有效期限；拖动前、拖动中每100ms及松开后检查网络和页面，短手势中发生的弹窗或页面变化可能在松开后的检查才发现。检测到重连先释放再重试，恢复后重新确认列表；不在持有按键时点击重试，也不盲目重复提交阶段选择。手动停止、截图/窗口/输入异常或检测到页面变化均中断拖动；停止后只允许清理已按下的按键，不继续移动、点击或退出。

设置页增加阵容下拉框，默认暗双子队，启动时固定本次选择。两队均按现有从右到左的盗贼、精灵师、战士、骑士顺序招募。

每个点击后的新截图同时检查选中证据和对应招募/升阶/离队按钮，同一种证据与按钮联合连续三帧后直接使用最后一帧按钮位置提交，不再分开等待按钮或重复选中确认。离队仍要求同帧depart_title，之后稳定Missing才记录离队；升阶仍须确认预期阶数结果。网络恢复清空稳定计数，不重复点击目标或提交；手动停止、窗口和有效超时守卫保持。冲突识别只覆盖已加载的名称模板，不新增跨阵容资源依赖。

### 5.2 地图与统一节点入口

地图同时满足左下英雄图标、至少一个点亮且带三角的可选节点、左上区域标题。外围、中心、深层分别为第一、二、三层；人数和探查等级不用于层数判断。

动态搜索可选节点，优先级为 `修整T0 → 精英T1 → 补给／事件T2 → 一般战斗T3 → 商店T4`。同级按中心Y从小到大；唯一候选直接选择，首领唯一可选时无需优先级。点击后使用统一 `node_enter`，按节点类型分支；返回地图后重新定位。

首次进入或各节点返回时，地图仍须连续3帧确认楼层、可选节点类型及节点位置。该次确认的最新MapView仅交给紧接着的选点使用一次，不再在探索主循环重复完整确认；缺少可复用结果时照常重新识别。新的截图、流程点击、网络恢复、换轮、楼层不符或会话清理使旧结果失效。点击前仍执行手动停止和窗口检查。三角识别、节点配对、优先级及稳定判断保持原样，三角上下跳动本身不参与地图稳定签名。

节点类型识别先在地图区域寻找可选三角，再在每个三角附近匹配七类节点。局部区域由现有node_triangle_max_dx/dy及最大节点模板尺寸推导，保留原关联允许的完整节点范围，并裁剪到场景ROI；重叠搜索结果按空间位置去重，仍要求三角唯一关联节点。各窗口复用三角识别时已经归一化的同帧地图像素，避免窗口随三角跳动时发生缩放取整漂移。默认局部窗口约316×334，不改变模板、阈值、三帧确认或优先级。

### 5.3 战斗与结算

分别确认一般、精英、首领准备页；有待上阵记录则先换人再开始战斗。用户确认关闭自动时圆环回到固定姿态。基准与非基准共用静止参考角度判断：中心A可见性≥0.75、圆环参考匹配≥0.75、最佳角度比非相邻候选领先≥0.04时，相对关闭姿态偏转≥10°立即确认自动已开启，不再累计旋转样本、净角度或方向一致率。偏差按180°周期计算；90°也是有效偏转，不再作为相邻帧歧义拒绝。图标隐藏或圆环不可靠返回未知，后续新帧独立重试。

基准尺寸保持原固定中心和点击位置；非基准保留真实客户区比例、有限相位候选和局部中心定位，圆环与点击使用同一个当前中心，不再要求三帧中心锁定。中心变动中断静止确认。偏差不足10°不立即视为关闭：每帧相对关闭参考偏差≤5°且图像可靠时，按100～250ms间隔连续确认三张新帧；第三帧直接授权单次开启，不再叠加外层三次确认。偏差介于5°和10°之间或证据不可靠时清空计数。删除1500ms时长、10样本要求及角度历史/范围统计，仅保留三帧计数和时间戳；正常100ms采样下约200ms完成。开启后清空旧证据，复核相对静止参考的偏转。确认开启后本局后续战斗不重复检查。

关闭证据在遮挡、圆环不可靠、过长间隔、时间倒退、中心变动及网络恢复后清空；结果优先、15秒有效时间、战败/网络/停止守卫和3秒结算观察保持。废弃的相邻圆环累计类、独立基准运动类及其参数已删除，不保留旧路径开关。

chaos_auto_recognition每段等待输出一次摘要：reference_angle_deg、reference_score、reference_margin表示当前图像相对关闭姿态的证据，reference_rejects统计参考匹配拒绝；first_visible_ms、first_active_ms、visible_to_active_ms区分首次可见及首次确认开启。另记录当前中心、是否定位、关闭计数/采样跨度、漏检及重置次数，跨度仅作诊断而不作为确认条件。网络恢复保留本段累计诊断，新一段等待重新计时。

| 类型 | 顺序 |
| --- | --- |
| 一般 | 升级／VICTORY触发观察 → 可选升级处理 → 确认VICTORY → 继续探查 → 地图 |
| 精英 | 升级／VICTORY触发观察 → 可选升级处理 → 战利品选择 → 精英完成领取 → 继续探查 → 地图 |
| 第一、二层首领 | 升级／VICTORY／剧情后结算信号触发观察 → 可选升级处理 → 战利品选择 → 首领完成领取 → 招募券处理 → 继续探查 → 下一层 |
| 第三层首领 | 等待星之旅程 → 关闭 → 研究选项确认大厅 |

精英和首领的奖励入口共同引用 `elite_choose_reward`，保留各自场景ROI；完成领取继续分别识别 `elite_claim_complete`、`boss_claim_complete`，避免把次元碎片卡片当作领取结果。第三层首领不等待VICTORY。

普通、精英和第一／二层首领每场最多出现一次升级弹窗。每1秒先检测升级标题，未命中同帧补查VICTORY，任一单帧命中即开始3秒观察窗口，每100ms重新截图。升级标题及关闭按钮联合三帧稳定后立即使用最后一帧位置关闭，无需等满3秒或再单独确认关闭按钮；保留300ms缓冲并直接确认后续结果。无升级必须观察满3秒后再确认结果；窗口结束时仍有不完整弹窗则继续等待完整证据，关闭后的残留也阻挡底层结果。所有阶段沿用本场剩余期限；网络重连暂停计时、清空稳定帧但不重置观察窗口和关闭标记。恢复时若错过VICTORY，允许从升级/结算页接续；首领剧情结束的明确结算信号也可接入。事件战及第三层首领保留原结果分支。日志记录首次信号、弹窗出现/完整/稳定、关闭提交及结果确认的分段耗时，以及每场升级与VICTORY各自的匹配次数和总耗时。

所有战斗检测FAILED，命中立即停止，不点击、不计完成轮数。首领所属层数在进入战斗前绑定，不根据准备页面推算。

### 5.4 修整、事件、补给与商店
