E7auto v1.2.2 x64 使用说明
============================

一、运行环境

1. 仅支持 Windows x64。
2. 无需安装 Python，也无需另外安装程序依赖。
3. 游戏进程名称必须为 EpicSeven.exe，游戏窗口标题必须为“第七史诗”。
4. 程序运行时需要 Windows 管理员权限。


二、首次使用

1. 从项目的 GitHub Releases 页面下载 E7auto_v1.2.2_x64.zip，并完整解压到
一个固定文件夹。
2. 不要直接在压缩包内运行，也不要只复制 E7auto.exe。
3. 启动《第七史诗》并完成登录，回到游戏主界面。
4. 双击 E7auto.exe。
5. Windows 弹出用户账户控制（UAC）时，确认程序来自可信来源后选择“是”。
6. 在“功能中心”点击“刷新秘密商店”卡片。
7. 在功能页输入本次允许消耗的天空石上限。
8. 如需购买友情点数，请点击“购买友情点数”右侧开关；圣约书签和神秘奖牌会始终购买。
9. 点击“启动脚本”。

游戏可以安装在任意磁盘或文件夹。程序会通过窗口标题“第七史诗”和进程名称
EpicSeven.exe 自动定位已经运行的游戏，不需要用户查找或填写安装路径。
游戏启动时可以位于前台，也可以被其他窗口覆盖。若游戏已经最小化，脚本会将
它恢复为普通窗口但不会主动切换到前台，确认恢复完成后再开始运行。


三、运行时快捷键

F5：结束本次自动运行。

悬浮窗在脚本运行或停止期间都可以直接拖动，松开鼠标时会保存位置，不需要按
快捷键切换移动模式。

点击悬浮窗左上角绿色背景的“收起”，悬浮窗会变为使用程序 Logo 的圆形图标。
圆形图标仍可随意拖动；单击图标即可恢复完整悬浮窗。每次启动脚本时都会先显示
完整悬浮窗。圣约书签和神秘奖牌两行统计使用绿色文字显示。


四、界面说明

天空石上限：限制本次运行最多允许消耗的天空石数量。

购买友情点数：开关启用后，本次运行遇到友情点数商品时会进行购买。只有开关
本体响应点击，标签和所在行的空白区域不会改变状态。

主窗口支持自由缩放、最大化和还原。较窄时功能卡片改为单列滚动；卡片背景图
始终等比例覆盖并按固定视觉焦点裁剪，不会拉伸变形。

悬浮窗会显示运行时间、各类商品购买数量、已消耗天空石、连续未出货次数和
当前状态。

刷新策略与“转运ing...”等待：

“转运ing...”表示程序按策略退出商店，在游戏主界面等待，属于正常运行流程。
等待期间耗时继续累计，购买数量、天空石消耗和连续未出货次数保持不变；
等待结束后会自动重新进入商店，恢复“刷新ing...”。无需手动点击商店或重启
脚本，等待期间仍可按 F5 结束运行。

当前策略为 13 / 13 / 13 / 10 次，阶段间等待 5 秒 / 3 分钟 / 5 秒。
如果一直没有发现可购买的圣约书签或神秘奖牌，且天空石上限允许继续刷新：
1. 连续刷新 13 次未出货：退出商店，在主界面等待 5 秒后自动重新进入。
2. 再刷新 13 次未出货（累计 26 次）：退出商店，等待 3 分钟（180 秒）后
   自动重新进入。这段较长的停留是预定等待，不代表卡死或异常中断。
3. 再刷新 13 次未出货（累计 39 次）：退出商店，等待 5 秒后自动重新进入。
4. 再刷新 10 次未出货（累计 49 次）：正常结束，退出商店并确认主界面后
   显示“已停止”。即使天空石上限尚未用完，也不会继续刷新。

仅在成功刷新并完整扫描顶部、底部商品后统计未出货次数；首次进入商店时
已有的商品列表不计入。发现任一可购买的圣约书签或神秘奖牌后，回到第一阶段，
连续未出货次数清零；友情点数和已购买状态不会重置策略。阶段切换本身不会
清零悬浮窗上的连续未出货次数，本轮已消耗天空石也不会因策略重置而清零。

每次刷新消耗 3 天空石。完整扫描当前列表后，如果剩余的天空石消耗额度不足
下一次刷新，会直接正常结束，不再执行后续转运等待。

3 分钟等待期间，游戏可能进入隐藏界面的待机状态；等待结束后程序会自动
点击唤醒，再进入商店。两次 5 秒等待不会执行该唤醒点击。以上时长仅为主界面
等待时间，不包含退出、唤醒、重新进入和识别确认所需时间。


五、文件说明

E7auto.exe：程序启动文件。

config 文件夹：程序配置和校准数据，请勿删除或随意修改。

assets 文件夹：图像识别模板，请勿删除、改名或替换。

PySide6、cv2、numpy、yaml 等文件夹以及各类 DLL/PYD 文件：程序运行依赖，
请勿删除或单独移动 E7auto.exe。

logs 文件夹：程序运行后自动生成，保存文字运行日志，不保存游戏截图。
正式成品与源码统一记录详细日志，包括运行环境、窗口尺寸、识别、输入、性能和最终停止原因，无需切换日志模式。报错后请及时将 logs 文件夹压缩提交，保留同一次运行的 .log 和 .log.1 等分片。默认保留 7 天内最近 20 次运行；每文件约 10 MB，每次最多 3 个历史分片和 1 个当前文件；目录容量目标为 500 MB。超限时整组清理最旧的已结束运行，不删除正在写入的日志。长时间运行会覆盖最早的详细过程，每个新分片重复环境摘要。


六、常见问题

运行中退出商店、长时间停留在主界面，是不是中断了？

先看悬浮窗状态。“转运ing...”对应第四节的策略等待，最长一次为 3 分钟，
耗时会继续累计，结束后自动返回商店；“重连中”表示正在进行网络恢复。
“已停止”、计时冻结并出现关闭按钮才表示本轮已经结束，但正常完成、F5 和
异常停止都会显示“已停止”，具体原因请查看 logs 中本轮日志的 run_stopped。
refresh_strategy_exhausted 表示四阶段一直未出货后按策略正常结束。
如果明显超过等待时长仍未恢复，可查看 refresh_strategy_wait_started 中的
等待秒数，以及重新进入商店后的 refresh_strategy_wait_completed 和最终
停止原因；需要反馈时请提交本轮完整日志。

1. 提示找不到游戏窗口

请确认游戏已经启动并登录，窗口标题为“第七史诗”，且 EpicSeven.exe 没有被
改名。不要同时启动多个符合条件的游戏窗口。

2. 点击开始后程序停止

程序采用安全停止策略。启动前已经最小化的游戏会先无激活恢复；脚本运行后再次
最小化游戏、尺寸调整失败、进程身份变化、识别结果不确定或输入验证失败时，程序
会停止，避免错误点击。可在 logs 文件夹中查看本次运行日志。

3. Windows 显示“未知发布者”或 SmartScreen 提示

当前版本没有数字签名。请只从项目 GitHub Releases 页面下载并运行完整压缩包。
不要关闭系统安全功能，也不要运行来源不明
的副本。

4. 是否可以只把 E7auto.exe 发给别人

不可以。E7auto.exe 依赖同目录中的配置、识别模板、DLL 和运行库。分发时必须
发送完整的 E7auto_v1.2.2_x64.zip；项目维护者通过 GitHub Releases 发布该文件，
不在源码仓库中保存本机构建目录或 ZIP。

八、注意事项

1. 当前识别和点击坐标以 2322 × 1306 游戏客户区为唯一校准基准。游戏所在
显示器的当前桌面分辨率不得低于 2560 × 1440。当前分辨率为 3120 × 2080 时，
程序使用原始 2322 × 1306 客户区；其他受支持分辨率会按完整显示器宽度的 60%
和固定宽高比调整窗口，完整窗口过高时会继续等比缩小。
2. 运行期间不要更换游戏所在显示器、修改 Windows 分辨率或显示缩放；检测到
显示器、分辨率或 DPI 变化时，程序会在下一次输入前停止。
3. 运行期间不要手动操作游戏或移动/最小化游戏窗口。正常完成时脚本会先退出商店并确认回到主界面，再显示悬浮窗“已停止”；按 F5 或发生异常时会立即安全停止，不追加退出商店操作。停止后可以点击悬浮窗右上角关闭按钮将其隐藏；这不会退出主程序，下次启动脚本时悬浮窗会重新出现。
4. 请根据自己的实际需求设置合理的天空石上限。
5. 如需立即停止，按 F5。
