# Architecture

## Data and threads

- The Qt main thread owns `MainWindow` and `StatsOverlay` only.
- `AutomationWorker` runs the session on a `QThread` and publishes frozen `RuntimeSnapshot` objects through Qt signals.
- `SnapshotPublisher` is the single counter source and emits the final snapshot once. Later mutation attempts are ignored.
- Overlay activity is snapshot state rather than widget inference: startup publishes `已启动`, confirmed shop entry publishes `刷新ing...`, strategy main-screen recovery publishes `转运ing...`, and finalization publishes `已停止`. The hotkey hint is static.
- `StopController` uses the same lock for F5 requests and input dispatch. Inputs already dispatched cannot be retracted; after F5 wins the lock, no new input callback can begin.

## Fail-closed flow

1. Main-thread configuration validation occurs before any worker or hotkey is created.
2. Because the observed game process runs at High integrity, the production process must also be genuinely Windows-elevated. The standalone executable embeds a `requireAdministrator` manifest; rejecting UAC prevents startup. Unsandboxed execution without UAC elevation is not equivalent.
3. The worker registers bare F5 before locating or manipulating the game window.
4. The same hotkey service registers bare F6. F6 pauses the shared controller before the overlay becomes mouse-interactive; the second F6 restores click-through and exact capture exclusion, saves the position, and resumes checkpoints/input dispatch.
5. The game window must be unique. Before any restore/focus/resize, the window monitor's full `Monitor` rectangle must agree with `EnumDisplaySettings(..., ENUM_CURRENT_SETTINGS)` and meet the configured `2560 x 1440` minimum. The exact `3120 x 2080` reference mode requests the calibrated `2322 x 1306` client; every other supported mode starts at 60% of full monitor width with the same aspect ratio and is uniformly reduced if its DPI-adjusted complete outer window would exceed monitor height.
6. The overlay must have exact capture-exclusion read-back before automation starts or resumes after movement.
7. Every capture/input safety point verifies that the window still exists, is foreground, and has exactly the prepared screen client rectangle. Ordinary captures cheaply recheck monitor identity/full bounds and window DPI. Every real input repeats the complete current-mode cross-check. Any monitor, mode, geometry, or DPI change terminates without live resize/recalibration.
8. Entry clicks occur only after stable template evidence. Every click/wheel dispatch rechecks the window under the input lock, moves and reads back the cursor, executes the platform call, and logs success only after that call returns. Inventory navigation sends six `-120` wheel events `100 ms` apart after the top viewport is exhausted. Post-wheel settling starts sampling after `100 ms`, checks downsampled pairwise motion every `100 ms`, requires two consecutive observations within `1 px` with phase response at least `0.80`, and fails closed at the original `800 ms` maximum. A stable candidate must still pass the calibrated full-resolution total translation/change gate before bottom scanning. The last three temporally separated settle frames then seed bottom recognition; an identical three-frame key completes immediately, while a mismatch retains its longest stable suffix and captures only the missing frames. Cached recognition time counts against the next `100 ms` capture deadline instead of adding a fresh blind wait. Navigation does not depend on fixed top/bottom anchors.
9. Main-screen detection is defined solely by stable recognition of the shop-entry icon. Its alpha-masked template excludes user-dependent wallpaper; no whole-main-screen template is used. After an entry click, the engine waits for stable shop-refresh recognition. On timeout it jointly checks the shop refresh control and main-screen entry icon; only a stable main-screen result permits another entry click, and the bounded sequence stops after three attempts. Strategy-driven exit first requires stable recognition of the calibrated shop-exit control, clicks its calibrated center once, and then requires stable main-screen icon recognition before any wait or re-entry.

## Inventory algorithm

Each refreshed inventory is processed as `stable top loop -> one downward scroll -> stable bottom loop`. The reference display path passes the captured ndarray through unchanged. On non-reference displays, one frame wrapper maps each requested baseline ROI to the actual client, crops first, resizes it back to the exact baseline ROI size once, and caches that result for all detectors using the same ROI; full frames and template assets are never rescaled. Recognition anchors remain in baseline coordinates and are mapped only immediately before guarded input. Inventory vision then compares only this run's enabled available/purchased target states. Slots already completed in the current inventory are excluded before template matching; each remaining slot keeps only the highest-confidence classification. Repeated purchased-state skips are emitted once as a per-scan summary rather than synchronously once per frame. A scan result becomes actionable only after the same ordered `(slot_id, target_id)` list appears for the configured consecutive-frame count; the empty result uses the same rule. Mandatory targets are always enabled, and Friendship Points are matched only for runs whose checkbox was selected.

Adaptive scroll logging is aggregate rather than per-sample event spam. `scroll_settle_trace` records sample times, pairwise shifts/responses/change fractions, consecutive-stability counts, actual settle duration, and early-exit saving. `scroll_verified` retains the full-resolution before-to-final displacement evidence and adds the settle summary. `performance_stage stage=scroll_to_bottom` reports both the configured maximum and actual settle time. The following bottom `inventory_scan` stage reports `cache_outcome`, cached-frame availability/usage, cached stable suffix, fresh-frame count, and residual cache wait so live evidence can distinguish a direct hit from bounded fallback.

Within either viewport, the first enabled match in calibrated slot order is purchased. An explicit success increments its target count, records that slot as completed for the current inventory, discards the old scan list, and immediately starts a fresh stable scan at the unchanged scroll position. A completed slot is suppressed even if stale recognition still reports its pre-purchase target. Scanning continues until the viewport has a stable empty result. The completed-slot set is reset only after a confirmed refresh. Purchases never trigger an upward scroll, and row 4 has no special branch.

Refresh is allowed only when `spent + fixed_cost <= limit`. First entry, re-entry, strategy/network recovery, ambiguity, and retry/failure boundaries require a fresh stable Sky Stone parse from the fixed top-right icon/plus and digit ROIs. After an exact confirmed refresh, the resulting balance is trusted only while the engine remains in the same certain in-shop state; an ordinary next refresh reuses that value instead of immediately rereading the same three frames. The engine clicks refresh once, requires both the refresh-specific prompt and blue confirmation button to appear stably, then clicks refresh confirmation once. Internal spending increases only when the post-confirm balance is stably equal to `before - 3`. The unchanged old value remains pending until timeout; any other stable delta terminates with `refresh_balance_mismatch` and no internal count. Frames that already show the exact expected balance also accumulate the next top inventory's stability, but no inventory action is allowed until exact balance confirmation succeeds. A concurrent stable top result is consumed once by the next cycle; otherwise the original independent stable top scan runs unchanged. If the refresh exactly consumes the budget, the new top and bottom viewports are fully scanned before the next refresh check terminates the run.

The 180-second strategy recovery can leave the main screen in its UI-hidden standby state. After that wait only, the engine sends one ordinary guarded click to the calibrated client center `(1161,653)` before the normal stable main-shop recognition and entry sequence. The 5-second recoveries skip the wake click.

Only a fully scanned inventory produced by a confirmed refresh advances the no-target strategy; the initial inventory does not. An available mandatory Covenant Bookmark or Mystic Medal resets the strategy immediately, while Friendship Points and purchased-state classifications do not. Consecutive no-target batches are `(13,13,13,10)`. Recovery after the first batch is stable exit, checkpointed 5-second main-screen wait, and stable re-entry; after the second it uses the same sequence with a 180-second wait; after the third it uses a 5-second wait. Completing the final batch raises `refresh_strategy_exhausted`. F5 and exact foreground/client geometry are rechecked throughout every wait. The currency budget is checked before recovery, so a run that cannot afford the next refresh stops without an unnecessary wait or exit.

Purchase result polling accepts only an explicit success or an insufficient-purchase-currency warning stable for the configured consecutive-frame count. A non-warning frame resets warning stability. Timeout is ambiguous and terminates without retry or count changes.

## Ports

`ports.py` defines replaceable runtime-integrity, window, capture, input, hotkey, overlay, clock, and logger interfaces. Offline tests supply only fakes. Live implementations are isolated in `platform_windows.py`; OpenCV recognition and inventory-scroll measurement are isolated in `vision.py` and accept in-memory arrays only.

Text logs include aggregate `performance_stage` records for inventory scans, scrolling, balance reads/waits, and refresh execution. Each record reports total duration plus capture, vision, and non-reference ROI-normalization counts/times; no performance path persists screenshots or writes per-frame timing files. F6 pause duration is excluded from active recognition and wait deadlines.
