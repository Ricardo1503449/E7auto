# 用户行为与运行策略

本页记录当前实现的详细行为。安装与启动见 [README](../README.md)，模块职责见 [架构说明](ARCHITECTURE.md)。

## 界面与运行流程

主窗口先显示可缩放的功能中心；点击 `刷新秘密商店` 卡片后进入该功能页。功能页包含天空石消耗上限的纯数字输入框、一个仅在直接点击开关本体时切换的 `购买友情点数` 开关、开始按钮和仅含 F5 的快捷键提示。圣约书签和神秘奖牌始终会购买；只有在本次运行开始前启用该开关时才会购买友情点数。一次有效启动会重置本轮所有计数，注册无修饰键的 F5，启动计时器，恢复上次保存的有效悬浮窗位置（首次运行则使用校准后的默认位置），并最小化主窗口。悬浮窗可在任意时刻直接拖动，并会在同一内容列中居中显示 `已耗时：x时x分x秒`、各目标计数、`已消耗天空石：spent / limit`、`已经x次未出货`、`当前状态：xxx` 以及永久显示的 `F5结束` 提示。确认进入商店前状态为 `已启动`；在商店操作时为 `刷新ing...`；策略退出到主界面并进入恢复等待后为 `转运ing...`；网络恢复路径活动时为 `重连中`；正常完成刷新流程时会先退出商店并确认主界面，再显示 `已停止`；异常停止或 F5 停止不会追加退出点击。停止后悬浮窗右上角会显示关闭按钮，点击只隐藏悬浮窗而不退出主程序；下一次启动脚本时悬浮窗会重新出现。网络恢复所用时间不计入识别超时预算；恢复后会还原此前的活动状态，所有既有稳定帧和精确余额门控保持不变。每次完整扫描刷新后的商品列表且未发现圣约书签或神秘奖牌时，界面显示的连续未出货次数会增加；该计数会跨越保持不变的 `13/13/13/10` 策略阶段边界，只有发现任一必买目标时才会重置。生产环境悬浮窗尺寸会根据最大显示值测量一次，并在整轮运行中保持固定；耗时更新只重绘对应标签。终止时计时器冻结，最后一份不可变状态快照继续显示。

详细停止原因和识别/输入事件只写入 `logs` 下每轮运行对应的 UTF-8 文本文件。日志保留同时受文件时间和文件数量限制。

只有当右上角稳定的天空石余额从刷新前数值精确变为 `before - 3` 时，本次刷新才会计数。天空石图标在完整顶部栏搜索带中定位；数字识别从图标右侧开始，读取同一基线上的第一组连续数字，并在远离数字串的铃铛等顶部控件前停止，因此不预设三位、五位或七位等位数上限。该搜索带与数字通道均使用基准坐标，并通过现有坐标变换适配受支持的不同分辨率。数值未变化时允许继续等待直至超时；稳定但差值不正确时会安全停止。精确的刷新后数值仅在引擎仍处于同一个确定的商店状态时复用；进入/重新进入、策略恢复或网络恢复、状态不确定、刷新重试或失败都会使其失效，并强制重新稳定读取。显示精确预期刷新后余额的帧会同时累积下一次顶部视口所需的三帧不变稳定性，但在余额门控成功前不会执行任何商品操作；如果并发结果不稳定，则回退到原有的独立顶部扫描。商品匹配会对每个捕获帧只准备一次 BGR 数据，并在模板计算前排除未启用的目标以及当前商品列表中已经完成的槽位，同时汇总重复的已购买状态跳过事件。汇总性能阶段日志会记录截图/视觉处理耗时，但不会保存截图。

连续未发现目标的策略只适用于成功刷新后产生的商品列表。如果没有可购买的圣约书签或神秘奖牌，则执行：`刷新 13 次 -> 退出，在主界面等待 5 秒后重新进入 -> 刷新 13 次 -> 退出，在主界面等待 3 分钟后重新进入 -> 刷新 13 次 -> 退出，在主界面等待 5 秒后重新进入 -> 刷新 10 次 -> 停止`。发现任一必买目标会将策略重置到第一个 13 次刷新阶段；友情点数和已购买状态不会重置策略。货币上限仍是独立的硬性限制，并会在任何恢复等待或退出前检查。策略耗尽时以 `refresh_strategy_exhausted` 停止，并保留最终悬浮窗。

只有主界面上的 3 分钟恢复等待可能触发游戏隐藏界面的待机状态。等待结束后，自动化会在经过完整安全检查后点击校准的客户区中心 `(1161,653)`，恢复主界面 UI，然后定位并点击商店图标。两次 5 秒恢复不会发送该唤醒点击。


## 校准、窗口与滚动策略

目前已经记录以下配置：可执行文件名 `EpicSeven.exe`、精确窗口标题 `第七史诗`、物理客户区校准基准 `2322 x 1306`、参考桌面模式 `3120 x 2080`、最低桌面模式 `2560 x 1440`、刷新费用、模板、完整的天空石数字 `0-9`、进入/退出/刷新/对话框/天空石/商品列表/金币不足的 ROI 与客户区点击点、六个互不重叠的商品槽位、向下滚动序列（`-120` 重复 6 次）、空列表稳定扫描时序（`100 ms`、3 帧、3000 ms 超时）、经操作者确认的 `18 px` 悬浮窗偏移 `(-252,-145)`，以及后台实时 `购买金币` 识别。程序通过精确窗口标题、进程 ID 和可执行文件名定位正在运行的游戏，因此无需配置游戏安装目录。终止条件检查在不发送输入且不保存截图的情况下，以 `0.9999991492` 的置信度连续通过 5/5 帧。设计中不使用固定的顶部/底部导航锚点。购买成功状态根据匹配到的商品槽位动态识别，不依赖相对于整个窗口的绝对结果 ROI。

窗口策略使用游戏所在显示器的当前有效桌面模式（物理像素），并要求它与 Win32 完整显示器矩形一致。仅 `3120 x 2080` 使用原始 `2322 x 1306` 零缩放路径；其他受支持模式先取完整显示器宽度的 60% 作为客户区宽度，再按基准宽高比计算高度，并在 DPI 感知的完整外框超过显示器高度时等比缩小。脚本启动不要求游戏位于前台：已恢复的后台窗口保持不激活，最小化窗口通过 `SW_SHOWNOACTIVATE` 恢复并在确认完成后继续。宽度低于 `2560` 或高度低于 `1440`、查询失败、运行中再次最小化、迁移显示器、改变分辨率或 DPI 时均在下一次输入前安全停止。非参考路径只在内存中按需裁剪并归一化基准 ROI，不生成缩放模板或完整缩放帧。

生产环境滚动路径固定为六次 `-120` 后台窗口滚轮消息，事件间隔 `100 ms`。第六次滚轮消息后不会固定等待 `800 ms`：程序先等待最短 `100 ms`，然后每隔 `100 ms` 获取 WGC 新帧并自适应检测列表是否已停止滚动。连续 `2` 次帧间相位平移不超过 `1 px` 且相位响应不低于 `0.80` 时，再校验整体向上平移超过 `300 px`，以及差异阈值 `8` 以上的变化像素超过 `30%`；通过后立即扫描底部商品。`800 ms` 仅作为该自适应稳定与位移校验的最长时限，到期仍未通过时运行将以 `scroll_verification_failed` 停止。生产环境还要求真正的管理员权限，并且在任何输入被认定为已发送之前，必须重新核对窗口身份、客户区、显示器、分辨率和 DPI；不会移动或读取物理鼠标作为输入门控。
